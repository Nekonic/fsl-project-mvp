Cloudflare's security events screen is counters, one time series, and "top events by source" - addresses, countries, paths, hosts - each a table of a dimension with its count. Igloo's write-up of a Korean SOC console adds the part that makes an address mean something: the device that raised an alert is obvious from the alert, but what its source address *belongs to* is not, so the console maps ranges to the name of the thing that owns them and shows that name beside the address. So the widgets are tables, one per dimension: source addresses, destinations, signatures, request paths. A bar chart of eight addresses says less than eight rows naming them, the zone they belong to and where they are. What is deliberately not here: anything about how this range is built. Which container bridges which network, and which segment has no sensor on it, are findings about the stack - they belong in DECISIONS and in a test, and a room watching traffic has no use for them.
